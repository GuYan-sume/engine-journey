## 关于 warning C4819（中文注释的坑）

第一次编译时可能会看到：

    warning C4819: 该文件包含不能在当前代码页(936)中表示的字符

原因：源文件是 UTF-8，而 VS 在中文 Windows 上默认按 GBK(936) 读文件，中文注释就对不上了。

两个解决办法，任选一个：

1. **加编译选项 `/utf-8`（推荐）**
   项目 → 属性 → C/C++ → 命令行 → 其他选项，填 `/utf-8`，确定。
2. **保存成「带签名的 UTF-8」**
   VS 里 文件 → 高级保存选项 → 编码选 `UTF-8 带签名`。

`month01` 里的示例文件已经处理好了，你新建文件时可以自己选一种。

> 小知识：这类问题就是词典里说的「字符编码」。以后你处理资源文件时还会再遇到它。

## 换电脑怎么办（2026-09-17 补充）

### 一句话结论

**版本号会不一样，功能一样。** 只要勾对「工作负载」和「组件」，两台电脑编出来的东西就是同一个结果。

### 仓库根目录那个 `.vsconfig` 是干什么的

它是一个「环境清单」文件。**在另一台电脑上：**

1. 装 Visual Studio Community 2022（免费版），安装时**先什么都别勾**，直接装个空的
2. 用 GitHub Desktop 把 `engine-journey` 克隆下来
3. 双击 `month01\week1\week01.sln` 打开
4. VS 会自动读到这个 `.vsconfig`，弹出提示：**「此解决方案需要一些未安装的组件」** → 点「安装」→ 等它自己装完

装完就跟你现在这台电脑一模一样了，不用你自己猜该勾哪个。

### 手动勾选的话（万一没弹提示）

在 VS 安装器里勾这一个：

- **使用 C++ 的桌面开发**（英文：Desktop development with C++）

它会自动带上下面这些你正在用的东西：

| 组件 | 干什么用的 | 什么时候会用到 |
| --- | --- | --- |
| MSVC 工具集 v143 | C++ 编译器本体（`cl.exe`） | 每天 |

| CMake 工具 | 跨平台的工程生成工具 | 第 3 周以后 |
| vcpkg | C++ 第三方库管理器 | 大二以后 |
| AddressSanitizer | 内存越界检查器 | 第 4 周 |
| GoogleTest / BoostTest 适配器 | 单元测试框架 | 大二 |
| ATL | 微软的老框架 | 大概用不上，装了就装着 |
